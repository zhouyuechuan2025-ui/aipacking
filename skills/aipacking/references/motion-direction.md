# 动效密度、推拉镜头与章节轴

先排侧边元素和图解的动作，再决定哪些关键落点值得轻推。普通真人段保持取景稳定，约每 1–3 秒可由标签入场、划线、状态更新或图解连线带出一次变化，具体节奏随语速和阅读停留调整。章节轴持续推进，每镜的主要变化由本段内容承担。

- **稳定口播与轻推**。稳定口播直接省略 `camera`。只有开场重音、关键结果或需要集中视线的落点才安排一次平缓轻推，随后自然回位。横屏可从 1.06–1.08 试起，按人物、手势和字幕空间调整。新稿默认用 `cameraIntent: "accent"`。普通真人累计达到 10 秒时至少选一个内容落点做明显的轻推。只有素材或创作确实需要完全稳镜头时，填 `cameraIntent: "steady"` 和具体原因。`camera.keys` 每项是 `[原片绝对秒, 缩放倍数]`，首尾覆盖镜头边界，相邻真人镜头倍率和焦点连续。实帧核对脸、手势和最长烧录字幕。
- **重点收窗**参考 Overlay Studio 的人物聚焦卡。用 `camera.windowKeys` 编排 `[绝对秒, 0–1 进度]`，从 0 平滑收到 1，镜尾回 0。真人按 16:9 缩到左侧，右侧信息按词分批出现。原字幕随真人画面保留一层。只在确实需要独立信息区时收窗，核对缩窗时字幕仍可读。仅收窗可只填 `camera.windowKeys`，真人窗内维持原倍率。单独输出透明层时，真人运镜需在最终合成里完成。
- **两侧**用已有的 SideCard、SideBlocks 等或 SideBeats。SideBeats 的 `side.variant` 支持 `tags`（短标签）、`signal`（重点揭示加底线）、`steps`（顺序编号轨）、`stack`（文字条）。`side.items` 按台词写 `{text, at, label?, highlight?}`，`at` 是绝对秒。同段动作沿用同一组版面，逐项建立。右边空间不足时用左侧或缩短文字，避开脸、手势、名牌和底部字幕。
- **顶部**用 `chapterTimeline`，每项 `{start,title}`。首章为 0，起点取镜头切点。沿全片宽度分段，播过的段保留填色，当前段继续推进。真人、全屏图解、B-roll 均显示，图解的标题和标签放在进度条下方。
- **全屏**随台词逐步完成。开头先让观众知道看什么，接着建立输入、连线、结果。长停留要让连线或重点状态仍有信息变化，避免只放一个空底等下个词。

新分镜用 `motionVersion: 2` 和 `chapterTimeline`。每镜增加 `beats: [{at,label,word,role}]`，给每次关键可见动作一个绝对秒。校验检查动作间隔、章节、镜头连续性和侧边入场数据。有运镜时再核对关键帧和缩放范围。相邻真人镜头核对边界倍率和焦点。第二审的生产计划复用章节轴、运镜和 SideBeats 参数，双审入口比对原数据。其他原模板的实际动效仍按样图和播放验收。

运镜和常驻分章编排参考 [Overlay Studio](https://github.com/jeszhou/overlay-studio)，组件在 Nana 工作台中用已有 Remotion 依赖实现。需让用户审动态时，在该版分镜获批后提交实帧，并可按用户要求补局部动态预览。
