# 前三秒强开场

来源：用户明确指出开头3秒必须呈现最强、最好的效果，现有包装太弱太淡。这个要求优先于正文的轻动作预算。修改Skill不等于任何新样片已获得审美验收。

## 设计顺序

先读开头台词、看人物和可用案例，从当前已验证的模板/组件中选择最强的语义表达，再补定制动作。第0帧已有构图、主元素与足够对比；不从空白、弱标题淡入或低信息量裸口播开始。画面在约0.2–1.2秒建立一次主高潮，之后留下可理解的结果画面；具体落点跟开场原声，时间区间是起点而不是强行截断台词的标准。

前三秒只讲清一个重点，但允许多层动作共同完成这一重点。大尺度变化、前后景遮挡、完整人像窗口变形、语义对象聚合/拆解、真实案例接管画面可组合使用。弱淡入、轻漂移或小幅推近可以是辅助，不能是唯一主动作。高潮必须改变观看状态：例如全屏口播收为完整窗口，成果扩展占据主视区；不能只加一个无关发光边框。

## 优先组合（按素材和台词选择，不固定轮播）

|路线|动作链|当前基础与需要补的部分|
|---|---|---|
|人物与巨字|首帧大尺度文字/完整人物 → 巨字错拍收缩落位、人物置于字前 → 主关键词归稳|RefSemantic backstage hero + 当前逐帧遮罩；退出及与下一镜头的连接须定制|
|成果接管画面|首帧先见最强真实成果 → 材料短促重组/推近 → 完整人物收窗、成果成为主角 → 停留|TechImpact / TechPresenter push；共享媒体时钟、连续窗口位置须按作业接好|
|案例爆发后聚合|首帧主案例 → 2–3个真实案例错拍进入 → 汇成一个结果/产品对象 → 停留|TechCollage / Gather；原型分段有缺口，不能把淡出称为完整对象转化|

按 reference-priority.md 优先复用3.0参考连续效果，其次2.0、1.0，最后才是原工作台最近两批；同批越晚输入越优先。不为凑“炸”而插入无关隧道、粒子雨或碎脸切条；真实口播保持一个清楚的完整主体。案例文字需阅读时减少快切，让高潮落在结果而不是高速翻截图。没有可用案例时选人物与语义文字路线，不伪造产品效果。

开场中的快运动之后及时归稳，避免三秒持续抖动或所有元素一直漂浮。结果停留从约0.8–1.2秒试起，信息多时更长。不要塞整段口播稿，主标题优先短关键词。保持人像原色、脸部可见和底部字幕安全区。

## 声音与接续

有真实本地声音素材时，主动作前可有短促上升音/掠过音，高潮有一个清楚的落点，随后配乐退让给口播；不要每层同时重击。保留唯一口播轨与口型同步。无额外声音时 `audio.status: original-only`，交付如实说明。当前视觉组件默认静音，声音必须实际配置混音，不能把字段写完当成听感完成。

3秒后的正文继承人物、结果卡或标题的位置；同一个对象从开场接入正文，避免第三秒硬切成另一套通用模板。静帧与计划校验无法证明视觉力度或音效听感，实际播放要单独检查。

## 计划字段与检查

在现有 `plan.json` 增加顶层 `opening`，不修改现有场景渲染字段。`beats` 写实际动作，按时间排列，并覆盖0–3秒。`primaryTechniques` 写实际采用的机制，不能列尚未实现的模板或抠像。`peakAt` 为主视觉高潮落点；`holdUntil` 为主结果稳定停留结束（后台低对比轻运动可继续）。

```json
{
  "opening": {
    "range": [0, 3],
    "firstFrameDesigned": true,
    "semanticAnchor": "开场原句或关键词",
    "primaryTechniques": ["foreground-occlusion", "kinetic-type"],
    "peakAt": 0.7,
    "holdUntil": 2,
    "beats": [
      {"start": 0, "end": 0.2, "action": "首帧巨字与完整人物已可见，建立主次"},
      {"start": 0.2, "end": 0.7, "action": "巨字错拍收缩落位，当前遮罩将人物置于字前"},
      {"start": 0.7, "end": 2, "action": "主词与人像归稳，保留结果阅读时间"},
      {"start": 2, "end": 3, "action": "同一人物窗口收向左侧，接入正文材料区"}
    ],
    "continuity": "人物和材料沿同一源时钟进入下一场景",
    "audio": {"status": "original-only", "reason": "未配置额外音效；保留原口播"}
  }
}
```

机制枚举：`foreground-occlusion`、`presenter-window-transform`、`object-morph`、`result-takeover`、`kinetic-type`、`case-montage`、`depth-parallax`。至少一项确实改变视觉状态的机制，而非淡入等装饰；组合数量不作为审美得分。

`node <skill>/scripts/check-opening-plan.mjs <工程绝对路径>` 检查新作业是否声明强开场、时间顺序与覆盖、高潮之后阅读停留、正文接续及声音状态。有音效时仍由 `mix-audio.mjs --check` 核对真实文件。机械检查PASS不代表效果够炸或用户通过。

渲染验证：检查0、0.2、0.5、1、1.5、2、2.5秒、3秒前最后一帧及主高潮前后各两帧。连续看0–5秒：第一帧是否已抓眼、高潮是否明确、结果能否看清、接正文是否顺畅、人像是否完整。技术检查与人工审美分别记录；用户指出“太弱”时，改动作尺度、层次、对象变化或时间关系，不能仅提高饱和度和音量。短于3秒的素材按实际时长另定开场，不为了通过字段检查复制或拉长口播。
