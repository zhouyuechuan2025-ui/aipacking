## 固定规范

- 画布固定 `1920×1080 / 16:9 / 30fps`。
- 人物默认居中，中心安全区默认 36%，所有人物页动效只进入左右侧带。
- 标题不得小于最终 1080p 的 52px；正文不得小于 32px；辅助标签不得小于 22px。
- 连续两个信息单元不得使用相同的视觉机制；文字、流程、图表、关系、证据之间轮换。
- 数据图表只用于真实数据或明确趋势；没有数据时使用流程、箭头或关系图。
- 编辑器外壳使用黑白灰、少阴影；1920×1080 画布里的动效模板使用 Cyber Apple Dark 多色体系。两者不可混淆。
- DataChart 和 DataDashboard 必须勾选“已确认存在真实数据”才能导出；流程、步骤、类别、能力集合和“专业度”等概念禁止伪装成柱状图。
- 截图与录屏必须先裁掉 Dock、无效浏览器顶部和空白；禁止拉伸，只能等比缩放与裁切。
- 提示词卡必须固定在左侧垂直居中，卡片底部不得进入画布下方 18% 的字幕安全区；正文长度自适应，不允许大框小字，也不能单独出现。
- 已下架“两端锚点标题”和“领域数据总览”，自动匹配与手动模板库均不可再使用。
- 导出前检查人物、字幕、卡片、连线、阴影和动画中间态是否重叠。
- 数字只能来自字幕中的真实指标、倍数、时长、明确序号或流程节点；禁止把装饰性的固定 `01` 带进不同内容。流程节点编号必须按节点位置动态生成。
- 顶部章节进度条由 SRT 章节时间自动生成，并随透明动效层一起导出；章节名称、区间和当前高亮必须与时间轴一致。

## 模板语义资格与唯一匹配

自动匹配必须先把 SRT 拆成完整信息单元，识别中心主体、关系类型、真实数量、步骤数量、证据对象和重点级别，再从通过资格的模板中选择唯一最匹配项。不得通过关键词轮换模板，也不得为了丰富画面虚构节点、步骤、数字或对比关系。

- 中心能力关系：必须有明确中心主体（如 Codex、某个 Skill、工具、系统或产品），文稿必须明确说明“四层/四项/四大能力”，并真实列出四个能力节点。三项、五项、泛泛的“能力很强”或未列节点时禁止使用。
- 数据仪表盘/图表：必须有至少两组可核验的“数字 + 指标名”；概念、流程和主观评价禁止图表化。
- 三步/四步流程：必须真实存在相应数量且有先后依赖的步骤。普通并列特性不能伪装成流程。
- 提示词卡：必须出现真实指令、提示词、输入或问答内容；只提到“提示词”这个概念但没有可展示指令时不使用。
- 前后对比/处理器：必须同时存在旧/新、前/后、不是/而是或明确状态变化两端。
- 核心数字：必须存在真实数字、时长、倍数、比例或明确序号，不能生成装饰数字。
- 能力标签/悬吊关键词/应用套件：必须真实列出至少三项并列对象；不从一句抽象描述中补造条目。
- 证据窗口/工作区/证据舞台：必须有明确截图、录屏、页面、界面、结果或证据对象。
- 步骤标题：只用于明确章节、序号或步骤节点。
- 金句/标题页：只用于明确结论、核心主张或强观点，普通说明句不升级成强结论。
- 同一模板不得连续出现；同一视频中单个模板原则上最多自动使用 2 次，只有没有其他语义合格模板时才允许例外。
- 逐词编辑排版：作为短完整句的克制回退；没有专用模板通过时优先使用，不强行套复杂结构。

若首选候选未通过资格，系统必须解释被拒原因并寻找下一个合格模板；最终只保留一个最高匹配模板。没有专用模板合格时使用克制的通用文字动效。

## SRT 原文与画面文案

- SRT 原文保留为时间、语义和字幕依据，不直接等同于动效卡片文案。
- 动效卡片生成前先删除“嗯、啊、呃、这个、那个、就是说、其实、然后、那么、所以说、我觉得、你知道、对吧”等口水词、语气词和无意义连接词。
- 再从完整信息单元中提炼中心主张；标题、金句、数字说明和节点文字按各自模板容量压缩，不逐字复述口播。
- 提炼不得改变事实、数字、产品名、因果关系和原意；提示词卡中的真实指令只去掉口播引导语，不擅自改写指令内容。
- 右侧检查器编辑的是当前选中的时间线卡片，修改必须立即写回该卡片的 settings，并同步预览、保存版本和透明 MOV 导出。

## Dribbble 灵感库

灵感库不是截图收藏夹，而是可执行的构图与运动语法。只抽象公开案例中的阅读顺序、层级、节奏和交互反馈，不复制具体作品、插画、品牌或文案。

| 灵感语法 | 适用内容 | 核心动作 |
|---|---|---|
| Kinetic Type / 动势大字 | 金句、结论、强观点、关键数字 | 关键词逐级切入、放大、锁定 |
| Bento Reveal / 模块拼图 | 多能力、多工具、功能集合 | 信息块按阅读顺序逐块展开 |
| Split Story / 左右叙事 | 前后、旧新、输入输出 | 两侧建立对照，再在关系线上收束 |
| Radial Hub / 中心辐射 | 一个核心连接多项能力 | 中心先出现，外围节点依次点亮 |
| Spotlight Stage / 证据聚光 | 真实页面、证据、成果 | 压暗环境，主证据进入聚光区 |
| Layered UI / 界面景深 | 浏览器、工作台、录屏 | 多层界面错位进入，形成空间纵深 |
| Signal Rail / 信号导轨 | 步骤、流程、章节推进 | 沿固定动线逐个点亮节点 |
| Card Orbit / 卡片环绕 | 多个成果、案例、封面 | 卡片围绕稳定路径轮播，主卡短暂突出 |

### 高频应用硬规则

- SRT 自动生成的每一个动效段必须绑定一个 `inspirationId`，覆盖率必须为 `100%`；JSON 中同时导出覆盖率和各语法使用次数。
- 相邻信息段优先切换视觉语法；选择器对刚使用过的语法施加强惩罚，避免连续重复造成模板感。
- 语法选择先按文案语义和组件兼容性，再按项目内使用频率轮换；不能为了“多样”选择不符合内容的图表。
- 每段在检查器中显示选择理由，并允许人工切换；人工调整写回项目 JSON，作为后续稳定偏好的依据。
- Kinetic Type、Bento Reveal、Signal Rail 用作高频基础语法；Spotlight Stage、Layered UI、Card Orbit 用于证据或成果段，不滥用。

## 截图与录屏当前边界

- 当前版本只支持人工导入、人工放置和关键帧调整，不做自动素材匹配；这是为了避免错配和重复返工。
- 已导入素材可选择左右同屏、嵌入卡片、主证据面板或全屏展示，可重复使用，不限制“一份素材只用一次”。
- 所有素材仍必须遵守：裁掉 Dock/无效浏览器栏、等比缩放、焦点区域不丢失、禁止挡脸、关键帧结束位置截图复核。

## 图标策略

- 通用操作图标使用项目内可控 SVG：输入、搜索、处理、结果、图表、流程。
- Codex、ChatCut、ChatGPT、GitHub 等品牌图标必须使用官方或用户确认的素材，不用 AI 仿制。
- 只有需要风格化物件、场景或复杂插图时才调用图像生成；生成结果必须进入项目资产目录并经过可读性、边缘和透明通道检查。
